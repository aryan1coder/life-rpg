# Final Production Data Architecture

This document describes the final, authoritative data architecture for the Life RPG application, cementing the transition from legacy mock state to a fully production-ready database schema.

## 1. Single Source of Truth
- **Authoritative Layer**: Supabase PostgreSQL and Supabase Auth.
- **Rules of Engagement**: 
  - `localStorage`, `sessionStorage`, and `IndexedDB` are strictly banned for gameplay data state.
  - The Next.js API and Server Actions are the primary arbiters of data fetching and mutation.
  - React Context (`GameContext.tsx`) is merely an ephemeral UI cache that listens to and reflects the backend truth.

## 2. Authentication Flow
- Leverages `@supabase/ssr` to establish standard, secure, HTTP-only cookie-based sessions.
- Session tokens are properly chunked and safely reconstructed in `src/lib/auth/session.ts` (`getAuthSession()`), preventing JWT malformation on browser reloads.
- `auth.uid()` acts as the foreign key anchor for all subsequent data relations.

## 3. Core Database Schema & Mappings

| Feature Domain | Supabase Table | Purpose |
| :--- | :--- | :--- |
| **Authentication** | `auth.users` | Secure identity management, password hashing. |
| **Profile & Role** | `public.profiles` | Core player entity, levels, XP, gold, and authorization (`role = 'player' | 'admin'`). |
| **Attributes** | `public.character_attributes` | 5-capacity stats matrix (Intellect, Discipline, etc.). |
| **Quests (Directives)** | `public.quests` | Active/completed user tasks. Seeded/default data eliminated. |
| **Economy/Rewards** | `public.rewards` | Admin-managed store items available for purchase with Gold. |
| **Inventory** | `public.inventory` | Ledger of rewards purchased by players. |
| **Avatar Loadouts** | `public.user_avatar_loadout` | Currently equipped avatar cosmetics. |

## 4. Admin Security Paradigm
- **Role Verification**: Admin privileges are not derived from hidden UI buttons or frontend state. They are rigidly enforced by querying `public.profiles.role = 'admin'`.
- **API Guarding**: All `/api/admin/*` endpoints extract the authenticated session, cross-reference the profile role, and throw a `403 Forbidden` if unauthorized.
- **Promotion**: Arbitrary users cannot elevate their status. Admin designation must occur securely (e.g., via the `public.promote_to_admin` PostgreSQL function, accessible only by `service_role` or existing admins).

## 5. Elimination of Mock Data
- The legacy `DataStore` mechanism (`src/lib/storage/data-store.ts`) has been sanitized.
- The `createStarterQuests` array has been completely removed.
- A new player registers and receives a blank slate (0 XP, 0 Gold, empty Quests list), representing a true "Day 1" production environment. All data observed in the UI is natively generated by user action and persisted to the database.
